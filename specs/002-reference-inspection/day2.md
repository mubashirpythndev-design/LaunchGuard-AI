# Day 2: Multi-angle inspection

Implemented on 2026-10-08. Day 2 covers four-view capture, orchestration, persistence,
aggregation, and a usable inspection workspace. ORB alignment, SSIM comparison, baseline
enrollment UI, and the comparison slider remain later-phase work. The UI explicitly states
that baseline comparison is not evaluated.

## API and persistence

`POST /api/inspections` accepts multipart `rocket_id`, `front`, `right`, `back`, and `left`.
The original multipart `file` request remains supported. Mixing both modes is rejected.
Quadrant uploads require an existing rocket. Each supplied image is validated for MIME type,
decodability, and the 10 MB limit before creating a run. No client-supplied file path is accepted.

A partial quadrant set creates degraded warning findings for every missing view; an empty
set is rejected. The UI requires all four images. Four captures represent four camera views,
not proof that every surface is visible or that alignment has been verified.

The endpoint commits the run and returns a handle before background processing. Checks run
off the event loop with bounded waits. Each quadrant's findings and progress events are
persisted and streamed. `runs.rocket_id`, `findings.quadrant`, and `inspection_images` preserve
vehicle association and source attribution. Initialization adds the nullable columns to
existing SQLite databases without deleting existing records.

Run details and reports include the quadrant image list. Original and annotated images are
served by `/api/runs/{run_id}/quadrants/{quadrant}/{image|annotated}`. Findings retain the
original check IDs; quadrant attribution distinguishes repeated checks. Frontend types are
generated by `pnpm generate`.

## Safety behavior

- The entire finding list goes to `rule_engine/verdict.py`; no quadrant votes or averages
  can suppress a critical defect. Existing critical findings are never downgraded.
- Missing, failed, timed-out, empty, invalid, or low-confidence checks cannot produce OK.
- Failed annotations add degraded warnings without discarding critical findings.
- The visual inspection produces HOLD when mandatory manual inputs are absent, unless
  critical findings already require NO-GO. Manual completion reevaluates all persisted views.
- Early manual completion is rejected until quadrant processing has finished.
- LangGraph also supports `quadrant_paths`, preserving results across manual-input interrupts
  without running CV again on resume.

## UI and verification

The inspection workspace includes vehicle selection/registration, four independent capture
previews, replacement/removal, image validation, streamed findings, manual clearance, and
quadrant-specific evidence in the report. Single-image inspection and demo access remain
under the Single image / Demo tab. Motion is not applied to decision-critical components.

Backend tests cover critical defects on each angle, persistence and report attribution,
missing coverage, invalid upload atomicity, timeouts, exceptions, low confidence, early
clearance, and graph checkpoint resume. Frontend tests cover upload readiness, removal,
multipart mapping, validation, and quadrant evidence isolation.

Browser verification uses `pnpm exec playwright test` with the API on port 8000 (one worker)
and web app on port 3000. Install the browser once with `pnpm exec playwright install chromium`.
The new end-to-end scenario checks real uploads, reports, browser errors, mobile overflow,
and disclaimer visibility, and writes desktop/mobile screenshots to `test-results/`.

Final verification: 108 backend tests, 52 frontend tests, and all 8 Playwright scenarios
passed. Strict mypy, Ruff, TypeScript, ESLint, design constraints, and the Next.js production
build passed. Desktop and mobile screenshots were reviewed. The backend suite reports two
existing Starlette status-code deprecation warnings; these are not failing checks.
